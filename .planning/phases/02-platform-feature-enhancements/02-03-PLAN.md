<objective>
Implement the WhatsApp / SMS notification alerts trigger framework (FEAT-04) and create a dedicated Delivery Partner Fulfillment view in the admin platform (FEAT-05) allowing one-click status transitions ("Picked Up", "Delivered") with live phone calling, Google Maps navigation, and delivery instructions.

Real-time customer communication via SMS / WhatsApp reduces order inquiries and improves trust (FEAT-04). A lightweight delivery fulfillment interface allows drivers and kitchen dispatchers to manage handoffs and doorstep deliveries seamlessly from any mobile or desktop screen (FEAT-05).

- `backend/services/communication.service.js` implementing WhatsApp & SMS template generation, phone normalization, and simulated/live provider delivery
- Integration of notification triggers into `orders.js` and `track.js`

- New `admin-dashboard/src/pages/DeliveriesPage.jsx` with active order cards, one-tap "Mark Picked Up" and "Mark Delivered", direct call links, and delivery coordinates

</objective>

<task type="auto" id="02-03-01">
<title>Create communication service for WhatsApp and SMS notification triggers</title>
<instruction>
Create `backend/services/communication.service.js`:
1. Implement helper to normalize Indian phone numbers to E.164 format (e.g. `+91XXXXXXXXXX`).
2. Implement `sendWhatsAppAlert(phone, templateType, data)` and `sendSmsAlert(phone, message)`:
   - Provide standard templates:
     - `order_confirmed`: "Namaskar {name}! 🍱 Your Navedyam order #{display_id} (₹{total}) has been confirmed! Estimated delivery: {eta} mins. Track live: {track_url}"
     - `out_for_delivery`: "Your Navedyam order #{display_id} is out for delivery! 🛵 Our delivery partner is on the way. Instructions: {instructions}"
     - `order_delivered`: "Your Navedyam meal #{display_id} has been delivered! 😋 Enjoy your authentic Haryanvi feast. Rate your experience in the app!"
     - `order_cancelled`: "Your Navedyam order #{display_id} has been cancelled ({reason}). If prepaid, refund will process within 2-4 business days."
   - If external provider keys are configured (e.g., Twilio / Gupshup via env vars), execute provider request. Otherwise, log clearly to server console with formatted prefix:
     `[WHATSAPP ALERT] -> To: {phone} | {message}`
     `[SMS ALERT] -> To: {phone} | {message}`
   - Wrap in `try/catch` so messaging errors never block HTTP order flows.
</instruction>

<task type="auto" id="02-03-02">
<title>Connect WhatsApp/SMS triggers to order lifecycle events</title>
<instruction>
1. In `backend/routes/orders.js`:
   - In `POST /api/orders`: for non-Razorpay orders (`cod`, `upi`), trigger WhatsApp & SMS confirmation alerts to customer phone.
2. In `backend/routes/payments.js`:
   - In `POST /api/payments/verify`: after signature is verified, trigger WhatsApp & SMS confirmation alerts.
3. In `backend/routes/track.js`:
   - In `PATCH /api/track/:orderId/status`:
     - When status changes to `out_for_delivery`, trigger dispatch WhatsApp and SMS alert.
     - When status changes to `delivered`, trigger delivered WhatsApp and SMS alert.
     - When status changes to `cancelled`, trigger cancellation WhatsApp and SMS alert.
     - Support `authorize('admin', 'delivery_partner')` so delivery partners can update order status.
</instruction>

<instruction>

Add `GET /api/admin/deliveries/active`:
- Query orders where `status` is in `['preparing', 'out_for_delivery']`.
- Populate customer details (`name`, `phone`) and item details.
- Sort by `created_at: 1` (earliest orders first for fulfillment priority).
- Return `{ deliveries: orders, count: orders.length }`.
